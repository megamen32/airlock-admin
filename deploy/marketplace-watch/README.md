# Проверка результатов регистраций

По прямому поручению владельца user timer на server-100 читает общий JSONL
каждые пять минут. Неизменившийся файл не вызывает модель. Новые результаты,
доступы и блокеры адресованные root передаются через существующий локальный
Agent Herder `/resume` в исходный Codex чат, только когда он idle/completed.
Активный чат, ожидание разрешения и ручная остановка сохраняются. Новая сессия
не создаётся; ZCode и его регистрации таймер не перезапускает.

`config.json` в `~/.config/airlock-marketplace-watch/` содержит `chat`, `task`,
`state` (абсолютные пути) и `session_id`. Код развёрнут в
`~/.local/lib/airlock-marketplace-watch/`, units — в `~/.config/systemd/user/`.
При первой установке `watch.py CONFIG --initialize` учитывает уже прочитанные
строки; повторная инициализация запрещена. Затем включается timer через
`systemctl --user enable --now airlock-marketplace-watch.timer`.

Неизвестный исход HTTP admission оставляет `inflight` в приватном state.json:
автоматических повторов нет. Владелец сверяет `input_id` с историей Herder и
только после установления результата отмечает события прочитанными либо
снимает `inflight` при доказанном отсутствии принятого входа.

Бюджет: лёгкий Python oneshot, RAM high32/max64 МиБ, swap0, CPU5%, tasks8,
один процесс/проверка под flock, файл до2 МиБ, state до4096 хешей (~300 КиБ),
без browser/build/GPU. При установке на100 доступно более43 ГиБ RAM; ожидаемо
обычно до6с на проверку, аварийный wall60с (HTTP timeout15с на вызов).
Измеренный read-only запуск: 0,10с, RSS17472 КиБ. Возобновлённый
Codex остаётся в существующем бюджете harness, не в oneshot cgroup.

Проверка: настоящий JSONL и запущенный user timer; реальный GET состояния
исходного чата. Автоматическое пробуждение после нового доступа требует
первого подходящего результата при неактивном root; оно не имитируется.
Остановка: `systemctl --user disable --now airlock-marketplace-watch.timer`.
