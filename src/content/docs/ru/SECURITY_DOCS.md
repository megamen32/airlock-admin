# Безопасность

GPT‑Админ даёт ИИ-агентам доступ к вашим серверам. Безопасность — главный приоритет.

## Модель аутентификации (кратко)

У GPT‑Админ три механизма аутентификации — детали в [Configuration → Auth model](./CONFIGURATION.md#auth-model):

1. **`CTL_TOKEN`** (Bearer) — admin API + веб-панель
2. **OAuth bearer** — эндпоинт `/mcp` (для MCP-клиентов)
3. **`ADMIN_PASSWORD`** — форма `/authorize` внутри OAuth-флоу

Плюс `SHELLMCP_TOKEN` для регистрации агент → хаб.

## Минимум привилегий

- **User-mode по умолчанию** — агент работает от пользователя, который его поставил, не от root. System-mode (sudo) — opt-in, только когда нужны привилегированные операции.
- **Allowlist команд** — ограничьте набор команд, которые агент может выполнять (`~/.config/gptadmin/allowlist.txt`).
- **Allowlist IP** — ограничьте, с каких IP можно достучаться до агента.

## Обращение с секретами

- **Секреты маскируются в логах** — токены, пароли, API-ключи вырезаются до записи в лог.
- **Режим «только локально»** — для команд с чувствительными данными агент можно настроить так, чтобы не возвращать вывод в хаб (выполнять локально, сообщать только статус).
- **Управляемые бэкапы** — перед редактированием файлов `file_backup` создаёт бэкап с TTL. Для критичных файлов (nginx, systemd, сеть) TTL по умолчанию длиннее.

## Режим подтверждения

Для критичных операций (удаление файлов, изменение сетевых настроек) хаб поддерживает **approve mode**: ИИ предлагает действие, хаб спрашивает подтверждение человека перед выполнением. Включается per-agent в `/admin` → Security.

## Ротация токенов

```bash
# Сгенерировать новый CTL_TOKEN
openssl rand -hex 32

# Обновить env хаба, перезапустить
sudo systemctl restart gptadmin_hub  # или: systemctl --user restart gptadmin_hub

# Если меняли SHELLMCP_TOKEN — обновите HUB_URL/TOKEN у каждого агента
# Конфиги Custom GPT / MCP-клиентов — обновите на новый CTL_TOKEN
```

Ротируйте сразу, как только токен утек. Вычистить утёкшее значение из истории коммитов — разовая мера, ротация — безопасный путь.

## Gateway-режим для MCP-серверов

Когда GPT‑Админ используется как защищённый прокси/релей, внешние клиенты должны подключаться к GPT‑Админ, а не напрямую к частным stdio или LAN-only MCP-серверам. Если клиенту нужна только одна возможность — отдавайте per-server URL:

```text
/server/{slug}/mcp
/server/{slug}/actions/openapi.yaml
```

Так upstream MCP остаётся частным, а GPT‑Админ применяет HTTPS, bearer/OAuth, аудит, маршрутизацию и очереди. Полную поверхность `/server/hub/mcp` давайте только тем клиентам, которым действительно нужен весь релей/админ.

## Чек-лист для прод-хардена

- [ ] `CTL_TOKEN` — сильное случайное значение (`openssl rand -hex 32`)
- [ ] `OAUTH_CLIENT_SECRET` задан (для `/mcp`)
- [ ] `ADMIN_PASSWORD` сильный
- [ ] Хаб за HTTPS (Cloudflare/FRP-туннель или nginx + Certbot)
- [ ] Задан allowlist IP агента (только хаб может достучаться до агентов)
- [ ] Файрвол: наружу открыт только порт хаба (25900); порт агента (25901) — внутренний
- [ ] Approve mode включён для критичных операций
- [ ] Логи ротируются (`logrotate` или `journalctl --vacuum-time`)
- [ ] Бэкапы настроены (TTL в `file_backup`)

## Аудит-лог

Каждая выполненная команда логируется с: временной меткой, агентом, командой, вызывающей стороной (какой ИИ / адаптер), кодом выхода. Смотреть в `/admin` → Logs. Экспорт для SIEM — `/admin/api/logs/export`.
