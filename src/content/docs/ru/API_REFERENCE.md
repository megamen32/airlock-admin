# Справочник по API

Конечные точки REST + MCP, предоставляемые концентратором.

## Краткая справка по аутентификации

| Конечная точка | Авторизация |
|----------|------|
| `GET /admin` | Базовый (`CTL_TOKEN`) |
| `GET /admin/api/*` | На предъявителя `CTL_TOKEN` |
| `POST /mcp` | Носитель OAuth |
| `POST /heartbeat` | На предъявителя `SHELLMCP_TOKEN` |
| `GET /servers` | На предъявителя `CTL_TOKEN` |
| `GET /api.json` | нет |
| `GET /openapi.yaml` | нет |
| `POST /authorize` | `ADMIN_PASSWORD` форма |
| `POST /oauth/token` | учетные данные клиента |

См. [Конфигурация → Модель аутентификации](./CONFIGURATION.md#auth-model).

## API администратора (`/admin/api/*`)

Аутентификация носителя с помощью `CTL_TOKEN`. Используется веб-панелью и пользовательскими действиями GPT.

###`GET /servers`

Список зарегистрированных агентов Shellmcp.

```json
{
  "servers": [
    { "name": "server-01", "url": "http://10.0.0.5:25901", "alive": true, "last_seen": "2026-06-29T10:00:00Z" }
  ]
}
```

###`POST /exec`

Выполните команду оболочки на целевом агенте.

```json
{
  "server": "server-01",
  "cmd": "systemctl status nginx"
}
```

Ответ (если длинный, сокращен для экономии токенов):

```json
{
  "stdout": "● nginx.service - The nginx HTTP server...",
  "stderr": "",
  "exit_code": 0,
  "truncated": false
}
```

Команды обычно выполняются от имени настроенного пользователя без полномочий root агента ShellMCP. Установить
`run_as_user: "root"` только для намеренной привилегированной операции; корень
ShellMCP без настроенного пользователя по умолчанию отклоняет обычные команды.

###`GET /tasks/{task_id}`

Получите статус фоновой задачи.

###`POST /file/backup`

Перед редактированием создайте управляемую резервную копию файла.

###`GET /system/info?server=server-01`

ЦП, ОЗУ, диск, время безотказной работы целевого агента.

Полная схема: импортируйте `https://became.bezrabotnyi.com/api.json` в свой клиент.

## Конечная точка MCP (`/mcp`)

Аутентификация носителя OAuth. Удаленный SSE MCP (Streamable HTTP).

Сюда подключаются клиенты MCP (Claude Desktop, Codex, OpenCode). Концентратор предоставляет
инструменты Shellmcp как инструменты MCP:

- `shell_exec` — запустить команду оболочки
- `file_read` — прочитать файл
- `file_write` — записать файл (с бэкапом)
- `file_backup` — создать управляемую резервную копию.
- `systemd_status` / `systemd_start` / `systemd_stop` / `systemd_restart`
- `system_info` — ЦП/ОЗУ/диск/время безотказной работы
- `system_health` — быстрая проверка работоспособности
- `dir` — перечислить каталог

См. настройку [Адаптеры → MCP client](./ADAPTERS.md#1-mcp-client).

## Конечные точки агента (shellmcp)

Они вызываются хабом, а не напрямую ИИ. На предъявителя `SHELLMCP_TOKEN`.

| Конечная точка | Метод | Цель |
|----------|--------|---------|
| `/exec` | ПОСТ | Запустите команду оболочки |
| `/file` | ПОЛУЧИТЬ/ОТПРАВИТЬ | Чтение/запись файла |
| `/dir` | ПОЛУЧИТЬ | Список каталогов |
| `/systemd/{action}` | ПОСТ | статус/старт/стоп/перезапуск/включение |
| `/system/info` | ПОЛУЧИТЬ | ЦП/ОЗУ/диск/время безотказной работы |
| `/system/health` | ПОЛУЧИТЬ | Проверка здоровья |
| `/heartbeat` | ПОСТ | Зарегистрироваться в хабе (вызывается агентом → хаб) |

## Схема OpenAPI

- `GET /api.json` — схема JSON (для импорта Custom GPT/Open WebUI)
- `GET /openapi.yaml` — Схема YAML

Они общедоступны (без аутентификации), поэтому пользовательский GPT можно импортировать по URL-адресу.

## Фоновые задачи

Длительные команды возвращают `task_id` вместо блокировки:

```json
{ "task_id": "abc123", "status": "running" }
```

Опрос с `GET /tasks/abc123` до `status: completed`. Это делает ИИ.
автоматически.

## Усечение вывода

Длинный stdout/stderr разбивается на части. Ответ включает в себя:

```json
{
  "stdout": "...first 1MB...",
  "truncated": true,
  "spilled_path": "/tmp/spilled.stdout",
  "preview_head": "...",
  "preview_tail": "..."
}
```

ИИ может прочитать дополнительную информацию по запросу посредством последующего звонка. Это экономит токены —
ИИ читает только то, что ему нужно ответить.

## Целевой контракт ретрансляции

Чтобы узнать о реле-концентраторе, позвоните по номеру `listMcpServers` перед набором `listMcpTools` или
`callMcpTool`, затем передайте возвращенный явный идентификатор сервера как `target`. Существует
нет `default` цели и `target: "default"` возвращает `400`.


## MCP для каждого сервера и прокси-сервер действий OpenAPI

GPTAdmin предоставляет доступ к каждому зарегистрированному серверу MCP через аутентифицированные маршруты для каждого сервера. Замените `{slug}` на `meta.public_mcp_slug` из `GET /mcp-relay/servers`.| Метод | Путь | Цель |
|--------|------|---------|
| `GET` / `POST` | `/server/{slug}/mcp` | MCP-совместимая конечная точка для одного сервера |
| `GET` | `/server/{slug}/card` | Карта обнаружения сервера |
| `GET` | `/server/{slug}/health` | Состояние сервера |
| `GET` | `/server/{slug}/actions/openapi.yaml` | Сгенерированная схема OpenAPI для пользовательских действий GPT |
| `GET` | `/server/{slug}/actions/openapi.json` | Та же схема, что и JSON |
| `POST` | `/server/{slug}/actions/tools/{tool_name}` | Проксирование вызова действия OpenAPI для одного инструмента MCP |

Схема действия генерируется на основе `tools/list` выбранного сервера MCP. Тело каждого запроса операции представляет собой инструмент MCP `inputSchema`. Ответ на вызов действия оборачивает восходящий результат MCP:

```json
{
  "server_id": "OpenMemory",
  "tool_name": "openmemory_query",
  "status": "completed",
  "response": {"content": []}
}
```

См. примеры [MCP Proxy Relay](./MCP_PROXY_RELAY.md)].
