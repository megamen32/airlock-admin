# Управляемое резервное копирование файлов GPTAdmin

`file_backup` — предпочтительный инструмент агента оболочки для резервного копирования перед редактированием файлов.
Он заменяет разовые файлы `cp file file.bak.$date`, которые разбросаны по диску.

Инструмент доступен на каждом виртуальном агенте `shell:*` через хаб:

- `action=backup` копирует файл или упаковывает каталог в управляемый объект резервного копирования.
- `action=list` перечисляет известные резервные копии в корне управляемого резервного копирования.
- `action=cleanup` удаляет истекшие или резервные копии старше, чем `max_age_days`.
- `action=restore` восстанавливает резервную копию по `backup_id`.

По умолчанию хранилище на целевом хосте:

```text
~/.gptadmin/file-backups/
```

По умолчанию срок хранения для новых резервных копий составляет `ttl_days=30`. Используйте `ttl_days=0` только для резервных копий, которые не должны автоматически истекать.

Каждая резервная копия имеет `meta.json` и неизменяемый `manifest.jsonl`. Очистка сканирует только этот управляемый корень резервного копирования, а не всю файловую систему.

Примеры:

```json
{"action":"backup","path":"/home/roomhacker/gptadmin/go-hub/internal/hub/server.go","ttl_days":30,"label":"before-admin-api-change"}
```

```json
{"action":"list","limit":20}
```

```json
{"action":"cleanup"}
```

```json
{"action":"restore","backup_id":"20260624_144633_host_abcd1234_label","overwrite":true}
```

Для привилегированных файлов передайте `use_sudo=true`; целевой хост должен разрешать неинтерактивный `sudo -n`.
