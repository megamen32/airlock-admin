**Сервер, который решает «кому можно», + руки на любой машине + ИИ-секретарь
сверху. Одна AGPL-экосистема.**

Это репозиторий-объединение: здесь живёт код **GPTAdmin** (MCP-хаб и агенты
для управления машинами) и вендорная копия **Airlock** (платформа аккаунтов,
прав и агентов). Мы управляем ими как одной системой и на их стыке строим
продукт.

> 🔧 Живой стенд — деплой, секреты, хранилище: **[AIRLOCK_ADMIN.md](AIRLOCK_ADMIN.md)**

## Airlock + GPTAdmin = ?

Ответ в четырёх пунктах:

- **GPTAdmin** можно поставить **куда угодно** — ноутбук сотрудника, сервер,
  даже телефон. И он умеет **всё на этом устройстве**: файлы, shell,
  процессы, браузер. Это *руки*.
- **Airlock** — наоборот: существует **только на сервере**. Зато отлично
  ведает правами и доступами: аккаунты, сессии, гранты, политики,
  подтверждения опасных действий, полный аудит. Это *пропуск*.
- **Лицензии совпадают** — обе AGPL-3.0, поэтому два продукта свободно
  объединяются в одну систему без юридических оговорок.
- Сверху — **ExManager**, ИИ-секретарь. Он превращает «руки + пропуск»
  в законченную экосистему.

```
   сотрудник (телефон / ноутбук / браузер)
        │   «найди мои файлы» · «собери презу» · «открой почту» · «напиши отчёт»
        ▼
┌─────────────────────────────┐
│   ExManager — ИИ-секретарь  │   лицо экосистемы, живёт в мессенджере и на веб-морде
└─────────────────────────────┘
        │
   ┌────┴────────────────────────────────┐
   ▼                                     ▼
┌──────────────────────┐      ┌──────────────────────────┐
│  GPTAdmin — руки     │      │  Airlock — пропуск       │
│  ставится на любую   │◄────►│  живёт на сервере;       │
│  машину; умеет всё   │ MCP  │  решает КТО и ЧТО можно: │
│  на этом устройстве  │      │  гранты, аппрувы, аудит  │
└──────────────────────┘      └──────────────────────────┘
```

## Что это даёт людям

- **Сотрудник** с любого компьютера или с телефона спрашивает свои файлы,
  просит собрать презентацию, открывает почту, составляет отчёт — у своего
  ИИ-секретаря.
- **Доступами управляет Airlock**: каждый агент действует под выданными ему
  грантами, опасные действия требуют подтверждения человеком, каждый шаг
  попадает в аудит.
- **Руководители** получают дашборд единого управления бизнесом: кто что
  делал, что одобрено, что заблокировано, где чьи машины.

## Что уже работает (не на бумаге)

- Публичный инстанс Airlock: **https://airlock.bezrabotnyi.com**
- Сквозной канарей экосистемы: чат в Airlock → агент `fleet-admin` →
  MCP-брокер → хаб GPTAdmin → реальная команда (`uptime`) на реальной
  машине — ответ вернулся в диалог. Опасные действия проходят штатный
  approval-флоу (агент просит → админ подтверждает → агент выполняет).
- Файловое хранилище агентов — на Яндекс.Диске через S3-шлюз (rclone),
  кэш в RAM.

Подробности, проверенные команды и грабли эксплуатации —
[AIRLOCK_ADMIN.md](AIRLOCK_ADMIN.md).

## Что в этом репозитории

```
go-hub/         # MCP-хаб GPTAdmin — проксирует команды агентам (Go)
go-shellmcp/    # shell-агент GPTAdmin — работает на целевых машинах (Go)
cli.py          # CLI `gptadmin` — setup, tunnel, status, logs
deploy/         # установщики, systemd, nginx
fleet-agent/    # агент-интегратор GPTAdmin × Airlock
docs/           # полная документация GPTAdmin (архитектура, API, безопасность)
admin-ui/       # веб-панель хаба
airlock/        # вендорный subtree airlockrun/airlock (v0.6.3, AGPL-3.0)
```

## Быстрый старт

### Airlock — серверная часть

```bash
cd airlock
make dev        # поднимает инфраструктуру (postgres, s3, ingress) + backend
```

Боевой стенд (systemd, ротация секретов, nginx, S3-шлюз на Яндекс.Диске)
собирается по проверенным шагам из [AIRLOCK_ADMIN.md](AIRLOCK_ADMIN.md) —
там же список известных ловушек.

### GPTAdmin — хаб и агенты

```bash
# хаб из исходников (Go 1.21+)
go run ./go-hub/cmd/gptadmin-hub

# тесты (Python 3.10+)
pip install pytest pytest-asyncio
pytest -q
```

Установщик на машину: `deploy/install.sh` (Linux/macOS),
`deploy/install_win.ps1` (Windows). Установщик печатает Hub URL, к которому
подключается любой AI-клиент.

Существующие legacy-токены остаются валидными, пока владелец явно не
выполнит их ротацию или отзыв (canonical rule: the owner **explicitly
rotates or removes** them).
