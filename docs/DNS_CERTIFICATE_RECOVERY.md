# Восстановление DNS-01 для существующего входа

На 2026-09-09 wildcard `*.t.gptadmin.bezrabotnyi.com` указывает на
`185.240.120.152`. На VPN2 и VUSA обнаружен сертификат, истёкший 28 августа.
VUSA также нестабильно доступен из VPN2; обновление сертификата не доказывает
исправление этой сетевой проблемы и не подтверждает готовность failover.

Действующий SpaceWeb auth hook `/root/certbot-sweb-auth.sh` добавляет TXT через
существующий `swebmimic editTxt`, но ждёт только 30 секунд. Все четыре
авторитетных NS возвращают TTL 600 секунд. Ошибка ACME `Incorrect TXT record`
совместима с кэшированием прежнего RRset; содержимое кэша CA не установлено.
Делегация уже указывает на SpaceWeb, TTL родительской делегации — 172800 секунд.

`scripts/certbot_dns_propagation_hook.sh` оборачивает существующий provider hook:
сначала получает TTL, вызывает hook, затем проверяет текущий challenge на всех
настроенных authoritative NS и выжидает прежний TTL с момента наблюдаемой
сходимости. Каждый challenge проверяется отдельно. Ошибки и timeout блокируют
validation. Нового DNS API или бесконечного retry-loop нет.

Значения по умолчанию для существующего SpaceWeb deployment (можно переопределить):

```sh
export DNS_AUTH_HOOK=/root/certbot-sweb-auth.sh
export DNS_AUTHORITIES='ns1.spaceweb.ru ns2.spaceweb.ru ns3.spaceweb.pro ns4.spaceweb.pro'
export DNS_PROPAGATION_TTL=600
export DNS_PROPAGATION_TIMEOUT=1200
```

Путь provider hook и authorities имеют эти значения по умолчанию: certbot
сохраняет путь auth hook, но не окружение исходной оболочки. Для другого
провайдера задайте постоянное окружение службы renewal или отдельный launcher.

Перед одиночным выпуском нужно исключить параллельный запуск текущего
`/root/cert-issue-loop.sh`. В certbot заменяется только `--manual-auth-hook` на
путь установленной обёртки. Два challenge могут занять более 20 минут.
Старая кэшированная делегация этим ожиданием не устраняется.

Известный отдельный дефект SpaceWeb cleanup: `info` возвращает имя TXT в поле
`domain`, а существующие клиенты читают `name`; удаление собственных записей не
срабатывает. Не удалять чужие TXT и не угадывать форму delete-запроса. Этот
helper не меняет cleanup API. Старые TXT не заменяют проверку наличия нового.

После выпуска: проверить SAN/срок сертификата, установить в фактически
используемый nginx vhost, выполнить `nginx -t`, reload и внешнюю проверку с
обычной TLS-валидацией. `/version` и OAuth discovery — промежуточные проверки;
готовность резерва требует авторизованного выполнения реальной безопасной
операции при недоступности основного узла.
