# Архитектура

GPT‑Админ — это **единый хаб MCP** с **тремя адаптерами**. Инструменты подключаются К хабу;
ИИ подключаются ОТ него.

```
   Инструменты MCP подключаются В            ИИ подключаются ВЫ (3 адаптера)
  ┌─────────────────┐          ┌──────────────────────┐
  │ shellmcp        │          │ Claude · Codex       │ (MCP клиент)
  │ chrome-devtools │  ──►  ┌──┴──────────────┐       │
  │ openmemory      │       │   GPT‑Админ     │  ──►  │ DeepSeek · Qwen  │ (расширение для браузера)
  │ любой MCP      │  ◄──  │   MCP hub       │       │ Alice · GigaChat │
  └─────────────────┘       └──┬──────────────┘  ──►  │ ChatGPT · OpenUI │ (Действие OpenAI)
                              │                │       └──────────────────────┘
                              ▼
                        ваши серверы
                     (Linux · macOS · Windows)
```

## Компоненты

### 1. Хаб (`go-hub/`)

Центральный процесс. Он:
- Принимает сердцебиения от агентов shellmcp (регистрирует их, отслеживает активность)
- Предоставляет удаленный SSE MCP по адресу `/mcp` для клиентов MCP (Claude, Codex, OpenCode)
- Предоставляет REST admin API по адресу `/admin/api/*` (используется веб-панелью + Пользовательскими GPT)
- Проксирует команды от ИИ к соответствующему агенту shellmcp
- Обрабатывает OAuth (для потока OAuth OpenAI SDK) и Bearer auth (CTL_TOKEN)
- Обслуживает веб-панель по адресу `/admin`

### 2. ShellMCP (`go-shellmcp/`, `client/`)

Агент, который работает на каждой целевой машине. Он:
- Регистрируется в хабе через сердцебиение (`POST /heartbeat`)
- Выполняет команды оболочки, файловые операции, действия systemd локально
- Возвращает реальный stdout/stderr в хаб, который возвращает его ИИ
- Работает на Linux, macOS, Windows
- По умолчанию работает в пользовательском режиме (без sudo), в системном режиме при необходимости

Основной реализацией является Go (`go-shellmcp/`). Python-клиент (`client/`) сохранен для совместимости.

### 3. Три адаптера

Хаб предоставляет три способа подключения для ИИ. Один и тот же хаб, те же возможности —
выберите то, что подходит вашему ИИ.

| Адаптер | Протокол | Для | Конечная точка |
|---------|----------|-----|----------|
| **MCP client** | MCP remote SSE | Claude Desktop, Codex, OpenCode | `/mcp` |
| **Browser extension** | userscript (Tampermonkey/Firefox) | DeepSeek, Qwen, Alice, GigaChat, ChatGPT (бесплатно) | внедряется в веб-интерфейс |
| **OpenAI Action** | REST + OpenAPI | ChatGPT Custom GPT, Open WebUI | `/admin/api/*` |

См. [Adapters](./ADAPTERS.md) для настройки каждого адаптера.

## Поток данных

Когда вы просите ИИ "перезапустить nginx на server-01":

1. **ИИ** решает вызвать инструмент (инструмент MCP / Действие OpenAI / внедренный блок mcp)
2. **Адаптер** направляет вызов в хаб (`POST /mcp` или `/admin/api/exec`)
3. **Хаб** ищет `server-01`, находит его агент shellmcp, пересылает команду
4. **shellmcp** на `server-01` выполняет `systemctl restart nginx`, захватывает вывод
5. **shellmcp** возвращает stdout/stderr в хаб
6. **Хаб** обрезает длинный вывод (экономит токены), возвращает адаптеру
7. **Адаптер** возвращает ИИ, который считывает результат и сообщает о нем

## Почему такая архитектура

- **Хаб и спицы**: одно место для управления аутентификацией, логированием, обрезкой, аудитом.
  Добавление нового ИИ = добавление адаптера, а не переписывание агента.
- **Нативно MCP**: хаб говорит на языке MCP, поэтому любой клиент MCP работает. И хаб сам может
  потреблять другие MCP (chrome-devtools, openmemory) — они становятся инструментами,
  доступными для каждого подключенного ИИ.
- **Самостоятельный хостинг**: ваши серверы, ваши токены, ваши данные. Ничего не покидает вашу
  инфраструктуру.
- **Любой ИИ, даже бесплатные**: расширение для браузера означает, что вам не нужен платный
  API. Бесплатные веб-чаты (Qwen, Alice, GigaChat) становятся клиентами GPT‑Админ.
