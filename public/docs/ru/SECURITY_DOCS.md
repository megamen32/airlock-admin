# Безопасность

GPT‑Админ предоставляет агентам ИИ доступ к вашим серверам. Безопасность является главным приоритетом.

## Модель аутентификации (сводка)

GPT‑Админ имеет три механизма аутентификации — см. [Конфигурация → Модель аутентификации](./CONFIGURATION.md#auth-model).
подробности:

1. **`CTL_TOKEN`** (Носитель) — API администратора + веб-панель
2. **Носитель OAuth** — конечная точка `/mcp` (для клиентов MCP).
3. **`ADMIN_PASSWORD`** — форма `/authorize` внутри потока OAuth.

Плюс `SHELLMCP_TOKEN` для регистрации агента → хаба.

## Наименьшие привилегии

- **Пользовательский режим по умолчанию** — агент запускается от имени устанавливающего пользователя, а не от имени пользователя root.
  Системный режим (sudo) можно использовать только тогда, когда вам нужны привилегированные операции.
- **Корневые службы не закрываются** — когда ShellMCP запускается от имени пользователя root, настройте
  `SHELLMCP_DEFAULT_USER`. В противном случае обычные команды отклоняются; они никогда
  молча наследовать корень. Используйте `run_as_user: "root"` или явный `sudo` только для
  намеренное привилегированное действие.
- **Список разрешенных команд** — ограничить команды, которые агент будет выполнять.
  (настроить в `~/.config/gptadmin/allowlist.txt`).
- **Список разрешенных IP-адресов** — ограничивает доступ к IP-адресам агента.

## Обработка секретов

- Секреты **маскируются в журналах** — токены, пароли, ключи API редактируются.
  перед входом в систему.
- **Режим «Только локальный»** — для команд с конфиденциальными данными агент может быть
  настроен так, чтобы не возвращать выходные данные в концентратор (запускаться локально, сообщать только о состоянии).
- **Управляемые резервные копии** — перед редактированием файлов `file_backup` создает резервную копию.
  с ТТЛ. Критически важные файлы (nginx, systemd, сетевые ресурсы) получают больше времени жизни на
  по умолчанию.

## Режим одобрения

Для критических операций (удаление файлов, изменение конфигурации сети) хаб
поддерживает **режим одобрения**: ИИ предлагает действие, хаб запрашивает
подтверждение человеком перед выполнением. Включите каждый агент в `/admin` → Безопасность.

## Ротация токенов

```bash
# Generate a new CTL_TOKEN
openssl rand -hex 32

# Update the hub env, restart
sudo systemctl restart gptadmin_hub  # or: systemctl --user restart gptadmin_hub

# Update each agent's HUB_URL/TOKEN if you changed SHELLMCP_TOKEN
# Update Custom GPT / MCP client configs with the new CTL_TOKEN
```

Немедленно выполните ротацию в случае утечки токена. Очистка утекшего значения из
исторические коммиты — это лишь разовая мера, ротация — безопасный путь.


## Режим шлюза для серверов MCP

Когда GPTAdmin используется в качестве безопасного прокси-сервера/ретранслятора, внешние клиенты должны подключаться к GPTAdmin, а не напрямую к частному stdio или серверам MCP, работающим только в локальной сети. Предпочитайте URL-адреса для каждого сервера, когда клиенту нужна только одна возможность:

```text
/server/{slug}/mcp
/server/{slug}/actions/openapi.yaml
```

Это обеспечивает конфиденциальность вышестоящего сервера MCP, в то время как GPTAdmin применяет HTTPS, аутентификацию носителя/OAuth, ведение журнала аудита, маршрутизацию и обработку очередей. Используйте полную поверхность `/server/hub/mcp` только для доверенных клиентов, которым необходимы возможности межсерверной ретрансляции/администрирования.

## Контрольный список производственного упрочнения

- [ ] `CTL_TOKEN` — сильное случайное значение (`openssl rand -hex 32`)
- [ ] `OAUTH_CLIENT_SECRET` установлено (для `/mcp`)
- [ ] `ADMIN_PASSWORD` — сильный
- [ ] Хаб находится за HTTPS (через туннель Cloudflare/FRP или nginx + Certbot)
- [ ] Установлен список разрешенных IP-адресов агентов (только концентратор может связаться с агентами)
- [ ] Брандмауэр: общедоступен только порт концентратора (25900); порт агента (25901) является внутренним
- [ ] Режим одобрения включен для критических операций.
- [ ] Журналы ротируются (`logrotate` или `journalctl --vacuum-time`)
- [ ] Резервные копии настроены (`file_backup` TTL)
